# BUG196 — GST & Invoice Test Cases (Generic)

Manual / UAT checklist for **multi-GST customer invoicing**, **place-of-supply (POS) rules**, **tax type (CGST+SGST vs IGST)**, and **accounts receivable (AR) posting**.

This document is **tenant-agnostic**. Use generic labels such as *Customer A*, *Branch KA*, *Branch MH*, and *Site in Karnataka* — not production customer names.

**Related:** `docs/modules/invoicing.md` · migration `V142__invoice_income_ledger.sql`

---

## 1. Scope

| In scope (v1) | Out of scope (v1) |

| Tax invoice create / edit / approve from SO or direct | Per-GSTIN AR ledger override (P5) |

| CGST+SGST vs IGST from **issuer branch state vs POS** | GSTIN prefix validation on customer **save** (only at invoice freeze in v1) |
| Invoice GST snapshots (GSTIN, POS, registration id) | |
| Receipt allocation across invoices | |
| Credit note uses original invoice tax snapshot | |
| Optional **other income** ledger on manual invoices | |

## 3. Business rules (reference)

### 3.1 GST selection priority (invoice create / SO bill)

1. **Site state** (+ city when multiple GST cards exist in the same state)
2. GST cards **linked to the issuing branch** (when branch links are configured)
3. **Primary GST** only if still no match **and** state matches (no silent cross-state primary)
4. **Blank GSTIN** if the customer is unregistered

### 3.2 UI rules

| Situation | Expected UI behaviour |
|-----------|-------------------------|
| Exactly one GST card matches branch + site | Auto-fill finance profile; field remains **visible** |
| Multiple possible GST cards | **Do not** auto-pick primary; user **must select** |
| Profile suggestion | Show GSTIN, state, bill-to address, and hint text (e.g. *“Suggested because site is Karnataka”*) |
| User changes GSTIN or site | **Recalculate tax immediately** |

### 3.3 Tax type

| Issuing branch state | Place of supply (site) | Tax on invoice |
|----------------------|------------------------|----------------|
| Same state | Same state | **CGST + SGST** (intra-state) |
| Different state | Any | **IGST** (inter-state) |

Tax is driven by **issuer branch GSTIN state vs site POS**, not by the customer’s primary registration state.

### 3.4 Ledger rules (v1)

- **One AR ledger per customer** — all invoices, receipts, and credit notes for that customer hit the same debtor account.
- **Approve** posts: Dr customer AR · Cr income (default or selected) · Cr applicable GST output ledgers only.
- **Freeze on save:** `customer_gst_registration_id`, GSTIN snapshot, POS snapshot, branch state snapshot.
- If approve fails, invoice stays **Draft** — no partial ledger lines.

### 3.5 Worked pattern (three invoices, one customer)

Assume **Customer B** has primary GST in Maharashtra and a second GST card in Karnataka. Sites exist in Pune (MH) and Bengaluru (KA). Your company has branches in both states.

| Invoice | Billing site | Buyer GSTIN on document | Tax | AR ledger |
|---------|--------------|---------------------------|-----|-----------|
| INV-1 | Maharashtra site | Maharashtra GSTIN | CGST + SGST (issued from MH branch) | Customer B AR |
| INV-2 | Karnataka site | **Karnataka GSTIN** (not MH primary) | CGST + SGST (issued from KA branch) | Same AR |
| INV-3 | Karnataka site, issued from **MH branch** | Karnataka GSTIN | **IGST** | Same AR |

Customer statement shows **one** outstanding balance. GST-wise sales reports still split by buyer GSTIN state.

## 5. Negative test cases

| ID | Scenario | How to reproduce | Expected system behaviour | Priority |
|----|----------|------------------|-------------------------|----------|
| **N1** | Multi-GST customer, no finance profile selected | Customer B; multiple valid cards; leave finance dropdown empty | **Block save** until GSTIN / finance profile is selected | **H** |
| **N2** | Silent primary fallback for wrong-state site | Site in State Y; only primary card is State X; no State Y card | **No silent fallback** to primary · Clear error: no GSTIN for site state; prompt to add card or select valid profile | **H** |
| **N3** | GSTIN registered state ≠ site POS | Manually pick GST card whose state does not match billing site state | **Block save** (invoice freeze validation) · Message identifies POS / GSTIN mismatch | **H** |
| **N4** | Multiple billing sites in different states on one invoice | Select Site KA + Site MH on same invoice | **Block save** · Message: one invoice cannot span multiple states; split invoices | **H** |
| **N5** | Selected GST registration inactive / cancelled / deleted | Draft with registration id; deactivate or delete card before approve | **Block approve** · Draft may retain id with validation error on approve | **H** |
| **N6** | GST card not linked to issuing branch | GST card has branch restrictions; issue from unlinked branch | **Block save or approve** · Message: registration not linked to issuing branch | **H** |
| **N7** | GSTIN numeric prefix ≠ registered state on card | GSTIN starts with wrong state code for card’s registered state | **Block save** on invoice freeze (and customer save when implemented) | **H** |
| **N8** | Issuing branch has no GSTIN | Branch master: `gst_number` empty; attempt tax invoice approve | **Block approve** · Message: branch GSTIN required for tax invoices | **H** |
| **N9** | UI tax type disagrees with POS vs branch | Force wrong tax display; approve | **Approve recomputes** from POS vs issuer branch · Server values win over stale UI | **M** |
| **N10** | Tax amount greater than taxable / imbalance | Lines where total tax exceeds taxable base | **Block approve** · Invoice remains Draft | **H** |
| **N11** | Customer AR ledger missing or inactive | Customer without provisioned or active debtor ledger | **Block approve** | **H** |
| **N12** | GSTIN override AR ledger inactive | Per-GSTIN override configured but ledger inactive | **Block approve** for that GSTIN | **L** |
| **N13** | Receipt posted to different AR than invoice | Attempt receipt allocation to wrong debtor account | **Block** · Receipt must credit the invoice’s customer AR | **H** |
| **N14** | Credit note after master GST change | Change customer primary GST after invoice approved; issue CN | CN uses **invoice snapshot**, never current master primary | **H** |
| **N15** | Inactive or draft customer | Customer status not ACTIVE | Allow draft if configured · **Block approve** until customer ACTIVE | **H** |
| **N16** | Duplicate GSTIN on two cards (same customer) | Save customer with same GSTIN on two registrations | **Block on customer save** | **M** |
| **N17** | SEZ GSTIN billed as normal intra-state | SEZ buyer; intra-state branch and site | Treat as **IGST** or export path · Do not post CGST+SGST split | **L** |
| **N18** | E-invoice required but GSTIN missing | B2B tax invoice above threshold (e.g. ₹50,000); no buyer GSTIN | **Block approve** or flag IRN path · Message references e-invoice requirement | **H** |
| **N19** | Change GSTIN after lines entered (sent invoice) | Approved/sent invoice | **Cannot change** GSTIN on sent document · Use credit note + new invoice | **M** |
| **N20** | Mixed CGST/SGST and IGST on same invoice | Lines computed as intra + inter on one document | **Block approve** · One POS, one tax type per invoice | **H** |
| **N21** | Other income invoice without income COA | Manual invoice with misc income intent; no `incomeLedgerId` | v1: may default to sales income · **Block approve** when income ledger is mandatory in your config | **M** |
| **N22** | Zero-value invoice with GST | Grand total = 0 but tax lines > 0 | **Block approve** | **H** |
| **N23** | Receipt with mixed override + default AR | Multiple invoices with different AR mapping (future P5) | Allocate per invoice to **each invoice’s AR** · Split receipt lines if needed | **L** |
| **N24** | Two GST cards, same state (+ same city) | Customer D; site matches both cards ambiguously | **Do not** auto-pick primary · Force explicit `customerGstRegistrationId` | **H** |
| **N25** | Missing GST output ledgers | COA missing CGST/SGST/IGST output accounts | **Block approve** with message listing missing ledger role | **H** |

## 7. Post-conditions verification

After each save or approve, verify:

### 7.1 Invoice record

| Field / check | Pass criteria |
|---------------|---------------|
| `customer_gstin_snapshot` | Matches selected finance profile GSTIN |
| `customer_state_snapshot` | Matches billing site POS |
| Intra-state | `cgst_amount` + `sgst_amount` > 0; `igst_amount` = 0 |
| Inter-state | `igst_amount` > 0; CGST/SGST = 0 |
| `customer_gst_registration_id` | Set and stable after save |
| `income_ledger_id` | Set when other-income path used (P8) |
| Status after approve | `SENT` (or your tenant’s posted status) |

### 7.2 Ledger voucher (approve)

| Entry | Pass criteria |
|-------|---------------|
| Debit | Customer AR — **one** ledger per customer |
| Credit — income | Default sales or selected income ledger (P8) |
| Credit — tax | Only applicable output ledgers (CGST/SGST **or** IGST) |
| Imbalance | Total debits = total credits |

### 7.3 Optional SQL spot-check

```sql
-- Replace schema and invoice id as needed
SELECT invoice_number, customer_id,
       customer_gst_registration_id, customer_gstin_snapshot, customer_state_snapshot,
       branch_state_snapshot, cgst_amount, sgst_amount, igst_amount,
       income_ledger_id, status, grand_total
FROM sales_invoices
WHERE id = :invoiceId;
```
